# RouteIQ — PatchTST Traffic Forecasting: Technical Documentation

## Overview

RouteIQ uses **PatchTST** (Patch Time Series Transformer) to forecast road traffic conditions 9 hours ahead, specifically to predict what traffic will look like at 5:00 PM given sensor data available at 8:00 AM.

This document describes the complete ML pipeline: dataset, feature engineering, model architecture, training procedure, evaluation methodology, and the 8AM→5PM validation framework.

## 3. Model Architecture

**PatchTST** (Nie et al., 2023) — Channel-independent patch-based transformer for time-series forecasting.

```
Input: [Batch, context_length=96, num_features=12]
  └─ Patching: 96-step sequence → 12 patches of length 16 (stride 8)
  └─ Patch Projection: Linear(16 → d_model=128)
  └─ Positional Encoding: learnable [1, num_patches, 128]
  └─ Transformer Encoder:
       - 3 layers
       - 8 attention heads
       - FFN dim = 512 (4 × d_model)
       - Dropout = 0.1
  └─ Flatten: [B×M, num_patches × d_model]
  └─ Prediction Head: Linear(num_patches × d_model → forecast_horizon=36)
Output: [Batch, forecast_horizon=36, num_features=12]
```

Key design: **Channel Independence** — each feature is processed independently, treating it as a separate batch dimension.

| Parameter | Value | Notes |

## 4. Training Procedure

### Data Splits (Chronological — NO shuffling)
```
Timeline: ──────────────────────────────────────
          [── 70% Train ──][── 15% Val ──][── 15% Test ──]
          1366 records      293 records    293 records
```

- **Train** (70%): Used to fit scaler and train model weights
- **Validation** (15%): Used for early stopping — model is saved when val loss improves
- **Test** (15%): Held out completely until final evaluation — **never seen during training**

### Optimizer
```
AdamW(lr=5e-5, weight_decay=1e-4)
ReduceLROnPlateau(patience=3, factor=0.5)
Gradient clipping: max_norm=1.0
```

### Baseline Comparison
Evaluated against `HistoricalAverageBaseline` which predicts the mean speed for each (day_of_week, hour) bucket from training data.

## 5. Evaluation Metrics

| Metric | Formula | Units | Measured on Test Set |
|---|---|---|---|
| MAE (Speed) | mean(|y_true − y_pred|) | km/h | **16.54 km/h** |
| RMSE (Speed) | √mean((y_true − y_pred)²) | km/h | **18.11 km/h** |
| MAPE (Speed) | mean(|y_true − y_pred| / |y_true|) × 100 | % | **69.70%** |
| Baseline MAE | mean(|y_true − y_hist_avg|) | km/h | **15.40 km/h** |
| Derived Accuracy Score | max(0, 100 − MAPE) | % | **30.30%** |

> **Important**: "Derived Accuracy Score" is a user-friendly proxy metric (100 − MAPE). It is NOT a standard ML classification accuracy. True accuracy for a regression model is measured by MAE/RMSE in original units.

## 6. 8AM → 5PM Evaluation Workflow

### Daily Cycle

```
08:00 AM (IST)
  └─ Scheduler: am_prediction_job()
  └─ Load all traffic_data up to 08:00 AM for each monitored segment
  └─ Build 96-step context window
  └─ Run PatchTST inference → step 36 = 5PM prediction
  └─ Store in MongoDB: forecast_evaluations collection
       { prediction_date, segment_id, predicted_speed, predicted_tci,
         prediction_time="08:00", target_time="17:00", evaluated=False }

05:00 PM (IST)
  └─ Scheduler: pm_actuals_job()
  └─ Collect fresh TomTom data for all 8 monitored hubs
  └─ Match to 8AM forecast_evaluation record by (prediction_date, segment_id)
  └─ Calculate: absolute_error_speed = |predicted_speed - actual_speed|
                pct_error_speed = absolute_error_speed / actual_speed × 100
  └─ Update forecast_evaluations: actual_speed, actual_tci, errors, evaluated=True
```

## 8. Model Versioning

Models are tracked in `ml/patchtst/checkpoints/model_registry.json`.

A new model version is **promoted** to production only if its validation MAE improves over the current active model.

| File | Description |
|---|---|
| `patchtst_traffic_v2.pth` | Current model weights |
| `patchtst_scaler_v2.pkl` | sklearn StandardScaler |
| `patchtst_metrics.json` | Latest training metrics with full provenance |
| `model_registry.json` | Version history with train/val/test metrics |

## 9. Known Limitations

1. **Limited real data**: Only 7 days of real TomTom observations (Aug 25–31, 2026). Model relies heavily on synthetic data for training. Predictions improve as more real data accumulates daily via the scheduler.

2. **City-wide corridor training**: The model is trained on combined segment sequences. Per-segment models will be enabled as each corridor accumulates 30+ days of data.

3. **Weather dependency**: Weather features are from Open-Meteo forecasts, not local physical sensors.

4. **Derived Accuracy Score ≠ Accuracy**: The "Derived Accuracy Score" metric (100 − MAPE) is a user-friendly proxy, NOT a standard ML metric.

5. **9-hour lookahead**: The 8AM → 5PM gap is 36 time steps at 15-min intervals. High variance during peak hours.
